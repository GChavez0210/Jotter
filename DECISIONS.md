# Architecture Decisions

## 1. Clipboard Architecture (`arboard::Clipboard::set_html` & `set_text`)
- **Problem**: Standard Markdown editors and browser-based webviews either collapse single `\n` line breaks into spaces (CommonMark soft-break rule), wrap paragraphs in `<p>` tags (which adds 8pt–12pt paragraph margins in Microsoft Word and Gmail), collapse leading/repeated spaces in HTML, or attach inline CSS font/background styles from the code editor DOM.
- **Decision**: Every copy operation in Jotter routes through Rust (`copy_to_clipboard`):
  - **Markdown source** (default): Writes two clipboard formats at once via `arboard::Clipboard::set_html(html, Some(plain))`:
    1. `text/plain` (`CF_UNICODETEXT`): raw Markdown source with normalized `\n` line breaks.
    2. `text/html` (`CF_HTML`): HTML-escaped raw Markdown generated by `plain_to_br_html`, where every `\n` becomes `<br>`, leading and repeated spaces become `&nbsp;`, and tabs become four `&nbsp;` (`&nbsp;&nbsp;&nbsp;&nbsp;`) so indentation survives in HTML targets.
  - **Plain** (opt-in "clean text" mode): Writes `text/plain` **only** via `arboard::Clipboard::set_text(plain)` with **no** `text/html` (`CF_HTML` is absent). Strips Markdown syntax (`#`, `**`, `*`, `~~`, `` ` ``, `[label](url)`, `[[Target|Alias]]` outside inline code spans) and drops code fence lines (` ``` ` and `~~~`) so the line count matches the code block content.
  - **Rich**: Writes both `text/html` and `text/plain` via `arboard::Clipboard::set_html(html, Some(plain))`. Renders inline/block Markdown via `comrak` per line, drops code fence lines (` ``` ` and `~~~`), preserves indentation and repeated spaces/tabs via `plain_to_br_html` (`&nbsp;`), leaves `[[wiki links]]` inside inline code spans untouched, and joins lines strictly with `<br>`.
  - **Safe Cut (`Ctrl+X`)**: In `Editor.svelte`, `cut` writes to the system clipboard first and dispatches the document deletion only after the clipboard write succeeds.

## 2. Desktop frames and opaque surfaces
- **Decision**: Use custom window controls on Windows and Linux. The macOS override enables native traffic lights with an overlay title bar and an opaque window.
- **Surfaces**: All platforms use opaque theme surfaces. Native window transparency, backdrop effects, their settings, and the app’s vibrancy dependency are removed.

## 3. Vault Storage, `.obsidian` Isolation, and SQLite Cache Location
- **Zero-Modification Guarantee**: Opening a vault, scanning its file tree, or reading a note never writes to the vault directory. `save_vault_note` compares the new content against the existing file bytes on disk and skips writing if they are identical.
- **`.obsidian` & Dot-Folder Exclusion**: Both `vault::scan_vault_snapshot` and `index::rebuild_index_from_vault` skip `.obsidian`, `.git`, and any dot-prefixed file or folder (including atomic write temporary files `.note.md.<pid>.<nanos>.tmp`).
- **Derived Cache Storage**: Per-vault SQLite databases (`indexes/<hash>.sqlite`) and `recent_vaults.json` are stored in the OS application data folder (`Jotter`) so Jotter never creates hidden database files inside the user's Obsidian vault.

## 4. SQLite Index, `edit_log`, & File Modification Times Under Sync Tools
- **Note on Sync Tools**: File synchronization tools (OneDrive, Dropbox, Syncthing, Git, Obsidian Sync) can alter filesystem `mtime` (`modified` timestamps) when syncing files across machines, which can skew a calendar view that relies solely on filesystem `mtime`.
- **Decision**: In addition to the rebuildable `notes_index` cache table, SQLite maintains an `edit_log (path, edited_ms)` table written on every in-app save (`record_edit_log`) and updated on note/folder rename (`rename_edit_log_paths`). `rebuild_index_from_vault` clears only `notes_index` and preserves `edit_log`. When indexing or rebuilding a note, its `modified_ms` column uses `MAX(edited_ms)` from `edit_log` when present and falls back to filesystem `mtime` otherwise.

## 5. File Watching, Incremental Indexing, & Safe External Reloads
- **Debounced Incremental Watcher**: File system events from `notify` are batched on a background worker thread with a ~300 ms debounce window. Instead of running a full vault rebuild on every file change, only the affected paths are incrementally updated via `index_single_file` / `upsert_scanned_note` and `delete_indexed_path` (with full `rebuild_index_from_vault` run only on vault open). Filesystem walking (`scan_dir_files_from_disk`, `scan_single_file_from_disk`) always runs outside the SQLite `Mutex<Connection>`.
- **Self-Write Suppression**: In-app atomic writes record their relative path and `Instant` in `recent_self_writes` (900 ms window) so the `notify` watcher ignores Jotter's own autosaves.
- **Conflict-Safe Reloading**: When an external edit occurs on an open tab's `.md` file, clean tabs reload automatically from disk. If a tab has unsaved in-flight keystrokes, Jotter displays a non-destructive reload banner ("Reload from disk" / "Keep my edits") so user typing is never silently overwritten.

## 6. System trash and portable filenames
- **Recycle Bin (`trash` crate)**: Deleting a note or folder uses `trash::delete` to move items to the system trash rather than permanently unlinking them with `remove_file` / `remove_dir_all`.
- **Portable Naming Rules**: Both the frontend (`src/lib/validation.ts`) and Rust backend (`vault::validate_entry_name`) validate new and renamed note/folder names against conservative shared-vault rules: reserved device names (`CON`, `PRN`, `AUX`, `NUL`, `COM0`–`COM9`, `LPT0`–`LPT9`, with or without extensions), invalid characters (`< > : " / \ | ? *` and control characters), leading dots, and trailing dots or spaces.

## 7. Live Preview Mode & Focus Mode Architecture (Milestone 3)
- **Viewport-Bounded Cursor-Aware Live Preview (`src/lib/livePreview.ts`)**: Live mode uses a CodeMirror 6 `ViewPlugin` that inspects only `view.visibleRanges` expanded by a 20-line margin above and below each visible range (`computeVisibleLineWindows`). Syntax tree iteration (`syntaxTree(state).iterate({ from, to })`), Obsidian `[[wiki link]]` scanning, and paragraph dimming (`dimInactiveParagraphs`) run exclusively on those visible lines and rebuild on `docChanged`, `selectionSet`, `viewportChanged`, and incremental syntax tree completion (`syntaxTree(update.startState) !== syntaxTree(update.state)`).
- **Table Pipe Escaping & Inline Code**: When decorating GFM tables in Live mode, pipes inside inline code spans (`` `a | b` ``) and backslash-escaped pipes (`\|`) are never replaced by `TablePipeWidget`.
- **Manual Performance Note (5,000-Line Note)**: Because Live Preview decorations, wiki-link scanning, and paragraph dimming are bounded to `view.visibleRanges` (+20 lines margin) rather than the full document, opening a 5,000-line Markdown note keeps typing and arrow-key cursor movement instantaneous ($O(\text{viewport lines})$ per update). To verify manually: open or paste a 5,000-line `.md` note in Live mode (with Focus Paragraph dimming enabled) and confirm continuous typing and up/down arrow-key navigation remain smooth with no frame drops.
- **Interactive Task Checkboxes**: Task list markers (`- [ ]` / `- [x]`) render as interactive checkboxes (`TaskCheckboxWidget`) in Live mode that toggle `[ ]` ↔ `[x]` directly in the underlying Markdown document when clicked.
- **Focus Mode (`Minimal` & `Zen`)**:
  - **Minimal (`Ctrl+Shift+M`)** hides the sidebar, tabs, formatting toolbar, clipboard inspector, and status bar, leaving only the centered ~700 px editor canvas and a thin, low-contrast title bar.
  - **Zen (`F11`)** enters native window fullscreen (`getCurrentWindow().setFullscreen(true)`) with only the text canvas visible.
  - Moving the mouse to the top edge (`clientY <= 12`) temporarily reveals the command bar and menu; pressing `Esc` exits back to the previous layout (`preFocusLayout`). All layout and focus preferences (`editingMode`, `focusMode`, `typewriterScrolling`, `dimInactiveParagraphs`, `sidebarWidth`, `sidebarCollapsed`) persist per window in `localStorage`.

## 8. Links, Backlinks, Full-Text Search (`tantivy`), Tags, Quick Switcher, & Calendar View (Milestone 4)
- **SQLite `links` & `note_tags` Tables (`src-tauri/src/index.rs`, `src-tauri/src/links.rs`)**:
  - `links (source_path, target, target_norm, resolved_path, heading, alias, line_number, line_context)` stores every outgoing `[[wiki link]]` outside inline/fenced code blocks with its 1-based line number (accounting for YAML frontmatter lines), trimmed line context, and index-time `resolved_path` (`NULL` when unresolved).
  - **Index-Time Wiki-Link Resolution (`WikiLinkResolver`)**: Each wiki link is resolved to a single vault note path using a 3-step precedence:
    1. **Exact relative path first** (e.g., `[[Specs/Plan]]` -> `Specs/Plan.md`).
    2. **Same folder as the source note** (e.g., `[[Plan]]` inside `Beta/Deep/Sibling.md` -> `Beta/Deep/Plan.md`).
    3. **Shortest path among notes with that stem** (tie-broken lexicographically).
    `query_backlinks_for_note` queries `WHERE l.resolved_path = ?1 AND l.source_path != ?1`, and `re_resolve_all_links` automatically re-resolves affected links whenever notes are created, renamed, or deleted.
  - `note_tags (path, tag)` stores unique normalized tags extracted from both YAML frontmatter (`tags: [a, b]` and multiline YAML list `- a`) and inline `#tags`. `extract_tags` rejects tags composed exclusively of digits (e.g., `#1`, `#2024`) and requires at least one non-digit character (e.g., `#v2`, `#2024-plan`), matching Obsidian.
  - Both tables are rebuilt on vault open and updated incrementally via `upsert_scanned_note` and `delete_indexed_path` on in-app saves, renames, deletes, and debounced watcher batches.
- **Full-Text Search (`tantivy` in `src-tauri/src/search.rs`)**:
  - **Single Long-Lived `IndexWriter`**: `VaultSearchIndex` holds a single `Mutex<IndexWriter>` created once at startup and reused across `rebuild_from_scanned`, `upsert_scanned_note`, `upsert_batch`, and `delete_path_or_prefix`. A second writer is never opened, and any commit failure returns an `Err` visible to the caller.
  - **Prefix Delete via `path_prefix` & Unstored Body**: Each document indexes `path` (`STRING | STORED`), `path_prefix` (`STRING`, containing one token for the note's exact path plus one token per ancestor folder prefix), `title` (`TEXT | STORED`), and `body` (`TEXT` only, **not** `STORED`). `delete_path_or_prefix` issues a single `delete_term` on `path_prefix_field` without scanning segments or reading stored documents. Because `body` is not stored in Tantivy's RAM directory (saving memory proportional to vault size), `search` reads matched `.md` files from disk (or falls back to the stored title in unit tests without a vault root) to generate `<mark>`-highlighted snippets and 1-based line numbers.
- **Wiki-Link Autocomplete & Click-Through Navigation (`src/lib/wikiLinkAutocomplete.ts`, `src/lib/livePreview.ts`, `src/lib/Editor.svelte`)**:
  - Typing `[[` triggers a CodeMirror 6 completion list of vault notes matching on both note title and relative path.
  - Clicking a rendered `[[wiki link]]` in Live mode (or `Ctrl+Click` on raw syntax in Source mode) resolves the target note in the vault using the same 3-step precedence and opens it in a tab; if `[[Note#Heading]]` is specified, the editor scrolls directly to the matching Markdown heading (`scrollToHeading`). If the target note does not exist yet, a prompt offers to create and open it.
- **Calendar View (`src/lib/CalendarView.svelte`)**:
  - Displays a month grid with dot + count indicators and heat-style shading for notes touched each day, with a `Modified` / `Created` toggle (`Modified` uses `edit_log` when present and falls back to filesystem `mtime`).
  - Supports full keyboard navigation on the month grid: `ArrowLeft`/`ArrowRight`/`ArrowUp`/`ArrowDown` move between days (automatically crossing month boundaries), `Enter` opens the focused day's note list, and `T` jumps to today.

## 9. Settings, Clipboard Image Paste, HTML/PDF Export, & Accessibility Pass (Milestone 5)
- **Settings Screen (`Ctrl+,`, `src/lib/SettingsModal.svelte`)**:
  - Organized into four sections with immediate persistence to `localStorage`:
    1. **Editor**: Default editing mode (`Live` vs `Source`), Typewriter scrolling toggle, Focus paragraph dimming toggle, Editor font size (`12`, `14`, `16`, `20` px matching the strict Fluent type scale), and Pasted image link syntax (`![[Pasted image ...png]]` wiki-embed vs `![](attachments/...)` standard Markdown).
    2. **Copy**: Default copy mode selector with detailed explanations of the three copy modes (`Markdown source`, `Plain`, `Rich`) and their clipboard format behavior.
    3. **Appearance**: Theme mode (`Follow System`, `Light`, `Dark`), writing font, and Accent color selector (`System Accent` using CSS `AccentColor` vs custom Fluent swatches/color picker).
    4. **Vault**: One-click **Rebuild Index** button (`rebuild_vault_index` IPC command that re-scans the vault and rebuilds both SQLite and Tantivy indexes while preserving `edit_log`) and **Show hidden files** toggle (default `off`; `.obsidian` is always ignored for vault safety).
- **Clipboard Image Paste & Live Mode Image Rendering (`src-tauri/src/media_export.rs`, `src/lib/Editor.svelte`, `src/lib/livePreview.ts`)**:
  - When pasting an image (`Ctrl+V`) in the editor, `Editor.svelte` checks `clipboardData.items` for `image/*` or invokes `save_pasted_image` in Rust, which reads raw RGBA pixels from the system clipboard via `arboard::Clipboard::get_image()` and encodes a valid PNG (`encode_rgba_to_png`) saved atomically to `<vault_root>/attachments/Pasted image YYYYMMDD-HHMMSS.png`.
  - Inserts either `![[Pasted image YYYYMMDD-HHMMSS.png]]` or `![Pasted image YYYYMMDD-HHMMSS.png](attachments/Pasted%20image%20YYYYMMDD-HHMMSS.png)` at the cursor.
  - In Live mode, `ImageEmbedWidget` resolves both `![[image.png]]` and `![alt](path)` on lines where the cursor is not resting via `read_vault_image_data_url` (checking `<vault_root>/<target>` and `<vault_root>/attachments/<target>`) and renders the image inline with a caption. Moving the cursor onto the image line reveals the raw Markdown syntax for editing.
- **Export to Self-Contained HTML & Print-to-PDF (`src-tauri/src/media_export.rs`, `src/App.svelte`, `src/app.css`)**:
  - **Self-Contained HTML (`export_active_note_html`)**: Renders the active note via `comrak` (with GFM tables, task lists, strikethrough, autolinks), converts Obsidian `![[image]]` and relative `![](attachments/...)` references into inline `data:image/...;base64,...` URLs so the exported `.html` file has zero external file dependencies, embeds Jotter's light/dark/print Fluent CSS, and prompts the user with a native desktop dialog through `tauri-plugin-dialog`.
  - **PDF via Print-to-PDF (`Ctrl+Shift+P` / toolbar button)**: Renders the active note HTML (including base64-inlined vault attachments) into `<div class="jotter-print-view">` and calls `window.print()`. In `src/app.css`, `@media print` hides `.app-shell` (`display: none !important`) and displays `.jotter-print-view` (`display: block !important`) with page-break control (`page-break-after: avoid` on headings, `page-break-inside: avoid` on code blocks, tables, and images) for the operating system print dialog and PDF output.
- **Accessibility & High-Contrast Pass Findings (`src/styles/design-tokens.css`, `src/app.css`)**:
  - **WCAG AA Contrast Audit**:
    - *Light Theme (`#ffffff` card / `#f3f3f3` surface)*: `--text-primary` (`#1b1b1b`, 17.4:1), `--text-secondary` (`#4f4f4f`, 8.1:1), and `--text-muted` (`#595959`, 7.0:1 on `#ffffff` and 6.2:1 on `#f3f3f3` — tightened from `#737373` which was 4.25:1 on `#f3f3f3`). Syntax tokens (`--syn-heading: #0055a6`, `--syn-code: #8c2d0f`, `--syn-link: #005fb8`, `--syn-meta: #595959`) all exceed 4.5:1 AA contrast on light surfaces.
    - *Dark Theme (`#282828` card / `#202020` surface)*: `--text-primary` (`#f5f5f5`, 14.2:1), `--text-secondary` (`#cccccc`, 9.8:1), and `--text-muted` (`#adadad`, 6.9:1 on `#202020` and 6.1:1 on `#282828` — tightened from `#9a9a9a`). Syntax tokens (`--syn-heading: #60cdff`, `--syn-code: #fbbf24`, `--syn-link: #4cc2ff`, `--syn-meta: #a8a8a8`) all exceed 4.5:1 AA contrast on dark surfaces.
  - **Windows High-Contrast (`@media (forced-colors: active)`)**:
    - Mapped all surface, text, border, and syntax CSS variables to semantic CSS System Color keywords (`Canvas`, `CanvasText`, `ButtonFace`, `ButtonBorder`, `Highlight`, `HighlightText`, `LinkText`, `GrayText`).
    - Added explicit `1px solid ButtonBorder` on interactive controls (`button`, `select`, `input`, `[role='tab']`, `[role='radio']`) and `2px solid Highlight !important` on `:focus-visible` so control boundaries and focus rings remain unmistakable when backgrounds are stripped by Windows Contrast Themes.
  - **Keyboard Reachability & Focus Rings**:
    - Every toolbar control, segmented radio button, tab, file tree item (`role="treeitem"`, `tabindex="0"`, `Enter`/`F2`/`Delete`), calendar day cell (`Arrow` keys, `T`, `Enter`), modal dialog (`Escape` to dismiss), and editor command is reachable via keyboard with a 2 px `--focus-ring` outline (`outline-offset: 2px`) and minimum `32 px` (`--control-min-height`) hit targets.

## 10. Roadmap Phase 1 Features
- **Recently Deleted (`src-tauri/src/recycle.rs`)**: Lists entries in the OS trash whose original path is inside the open vault, limited to `.md` files and folders, and restores them with `trash::os_limited::restore_all`. Restore refuses to overwrite a file that now exists at the original path. The `trash` crate supports listing only on Windows and Freedesktop Linux; macOS shows Finder Trash restoration guidance.
- **Daily Notes (`vaultStore.openDailyNote`)**: `Ctrl+Shift+D` opens `<folder>/YYYY-MM-DD.md` (folder defaults to `Daily`). A missing note is created from the template note (default `Templates/Daily.md`, falling back to a built-in template) with `{{date}}`, `{{title}}` and `{{time}}` filled in.
- **Summon Hotkey, Tray, and Close Button (`src-tauri/src/tray.rs`)**: Three independent settings, all off by default. The hotkey registers through `tauri-plugin-global-shortcut` on the Rust side, so the frontend needs no plugin permissions. Tray residency shows the icon, and the close button either quits or hides the window. Rust refuses to hide the window unless the tray icon or the hotkey can bring it back, and the Settings dialog turns the tray on when the user picks hide-to-tray, so the two guards agree. Tray **Quit** emits `quit-requested`; the page flushes autosaves and calls `quit_app`, and Rust exits after 5 seconds if the page never answers.
- **Single Instance (`tauri-plugin-single-instance`)**: Registered before every other plugin, so a second launch hands its arguments to the running app and exits before building any state. The callback unminimizes, shows, and focuses the main window, which covers a window hidden to the tray. The lock is per user, not per data folder, so `scripts/verify-desktop.mjs` requires that no other Jotter is running.
- **Math and Diagrams (`src/lib/richBlocks.ts`, `src/lib/livePreviewBlocks.ts`)**: KaTeX renders `$…$` and `$$…$$`; Pele renders ```` ```mermaid ```` blocks to SVG themed through `--pele-*` CSS variables. Both libraries load on first use. Inline math decorates visible lines in the Live Preview view plugin and follows Pandoc's `$` rules, so `$5 and $10` stays text. Block math and diagrams come from a `StateField`, because CodeMirror accepts block widgets only from state fields; the block list is rebuilt on document changes, not on cursor moves. With the cursor inside a block, the source shows with a rendered preview below it.
- **Export of Math and Diagrams**: comrak's `math_dollars` extension marks math as `<span data-math-style>`. The frontend replaces those spans and `language-mermaid` blocks before saving. HTML files get KaTeX MathML output, so the file needs no fonts or stylesheet; print uses KaTeX HTML styled by the stylesheet the app already loaded. `export_active_note_html` therefore receives finished HTML instead of Markdown.
- **Spell Check**: Jotter dictionaries are the default engine. The optional System engine delegates underlines and suggestions to the WebView; its coverage depends on the operating system. Only Jotter dictionaries support per-note languages.
- **CSS Snippets (`src-tauri/src/snippets.rs`)**: `.css` files in the app data `snippets` folder load as `<style>` elements after the theme, one per enabled snippet. The folder sits outside the vault so Jotter never writes there and never loads Obsidian's snippets, which target Obsidian's DOM.
- **Typo-Tolerant Search (`src-tauri/src/search.rs`)**: Plain word queries combine the exact query, boosted 4×, with `FuzzyTermQuery` clauses: 0 edits for words up to 3 characters, 1 edit up to 7, and 2 beyond, with transpositions counted as one edit. Queries that use operators, field names or quotes run exactly as written. Snippet highlighting applies the same edit-distance rule per word.

## 11. Roadmap Phase 2 Features
- **Calculations (`src/lib/calc.ts`, `src/lib/calcPreview.ts`)**: A recursive-descent parser evaluates expressions, so note text never reaches `eval` or `Function`. Results are widgets, not text, so the file changes only when the user accepts an inline result. An inline expression must contain an operator or function, starts at a word boundary, and never starts with a sign followed by a space, so list markers and prose such as `x = 5` or `Version 2 =` stay text. Implicit multiplication applies only before a name or parenthesis (`2pi`, `3(4+1)`), never between two numbers, so `items 3 2*4 =` gives 8, not 24. `a + b%` adds `b` percent of `a`, as calculators do.
- **Properties (`src/lib/frontmatter.ts`, `src/lib/PropertiesPanel.svelte`)**: Jotter has no YAML dependency. The parser handles scalars, inline lists, and block lists, and marks anything else (nested maps, `|` and `>` blocks, anchors) read-only. Each property keeps its source lines, and an edit replaces only those lines, so comments, key order, and untouched values stay byte for byte. Edits dispatch through the editor (`Editor.applyChange`) so they join the undo history and the normal autosave path. YAML cannot record the type of an empty value, so a type chosen for an empty property lives in the panel until the value is set.
- **Hidden Frontmatter in Live Mode (`src/lib/frontmatterPreview.ts`)**: A block replace decoration hides the YAML, an atomic range makes the cursor skip it, and a transaction filter moves an empty cursor below it, so typing never lands above the closing fence. New editor states in Live mode start with the cursor below the frontmatter.
- **Outliner (`src/lib/outliner.ts`)**: An item's block is its line plus following lines indented deeper, with blank lines included when deeper lines follow. Indenting aligns the item with the previous sibling's text column (2 for `- `, 3 for `1. `), or adds one tab when the list uses tabs, so the result stays valid CommonMark nesting. Outdenting aligns with the parent's marker. Fold arrows are widgets positioned in the left margin rather than a fold gutter, because a gutter narrows the centered text column and breaks its alignment with the note header. Zoom hides the text outside the item with block replace decorations and clamps the cursor inside it.
- **Cloud Folder Sync (`src/lib/syncConflicts.ts`)**: Sync clients already move files between machines, so Jotter's part is detection and guidance. The sync client is guessed from the vault path segments. Explicit conflict names (Dropbox, Nextcloud, Syncthing) always count. Ambiguous names (`Note (1)`, `Note-DEVICE`, `Note 2`) count only when the vault is inside the matching client's folder and the original note exists. Jotter never deletes or merges a copy on its own. Indexes and `edit_log` stay in the local OS application data folder per machine (decision 3), so sync clients never see database files.
- **Task Due Dates (`src-tauri/src/tasks.rs`, `src/lib/dueDates.ts`)**: Jotter reads the three due-date syntaxes Markdown users already write (Obsidian Tasks `📅`, todo.txt `due:`, Dataview `[due:: ]`) instead of inventing one. Only checklist items with a due date go into the `tasks` table; `[-]` and other custom states are skipped. The Rust parser and the TypeScript chip matcher follow the same rules, and both test the same cases.
- **Calendar File**: Calendar apps subscribe to a file or URL, so Jotter writes a plain `.ics` file to a path the user picks, never into the vault by default. Open tasks become `VEVENT`s, because Outlook and Google Calendar ignore `VTODO`. Dates without a time are all-day events, and times are floating local times. `UID`s hash the note path, text, and date, so an unchanged task keeps its identity across rewrites. The frontend rewrites the file 2 seconds after the index changes, and the backend skips the write when only `DTSTAMP` differs, so sync clients do not upload a new file on every keystroke. The path is stored per vault in local storage, since it is a per-computer location.
- **Note Cards (`query_note_cards`)**: One query returns every note's metadata, tags, outgoing resolved links, and the number of distinct notes linking to it. The Home page and the tags-and-links view both build on it in TypeScript (`src/lib/noteGraph.ts`), which keeps their logic testable without Tauri. The frontend reloads cards only when `indexVersion` changes.
- **Home Page**: A note appears only in the first section that matches it, as the roadmap specifies. Rediscover picks from notes unmodified for 90 days with a hash of the date, so it shows the same note all day. Recently opened history and the section layout are per vault in local storage. Property filters are not implemented yet: note cards do not carry frontmatter values.
- **Narrow Windows (`src/lib/layout.ts`)**: One rule decides when the sidebar fits: the window needs the sidebar's own width plus a 360 px text column. The resize handler stores the window width, and `sidebarAutoHidden` derives from it, kept apart from the persisted `sidebarCollapsed` so a narrow session never rewrites what the user chose; widening the window therefore brings back a sidebar the app hid, but not one the user collapsed. Asking for the sidebar in a window too narrow for it widens the window to exactly that sum rather than refusing, which needs `core:window:allow-set-size` since `core:window:default` omits it. The window minimum is 480 px, below which the title bar's drawn window controls would clip; between 480 and 600 px the title bar renders its mode switch as icons with `aria-label`s, since the labels are what push it past the edge. The thresholds live in `designTokens.ts` and are covered by tests, because the layout they protect cannot be checked without a real window.
- **Tags and Links View**: It reuses the Notes view slot with a Folders / Tags & links switch rather than adding another sidebar view, since both answer "where is my note". Link chains stop at notes already on the current path, so cycles cannot expand forever.
- **Spelling Dictionaries (`src-tauri/src/spell.rs`, `src/lib/spellcheck.ts`)**: The WebView checker cannot switch languages per note, so Jotter checks spelling itself with `spellbook`, a pure-Rust Hunspell reader that needs no C library on any platform. The dictionaries come from wooorm's `dictionary-*` npm packages, which convert LibreOffice's dictionaries to UTF-8; `tauri.conf.json` copies them from `node_modules` into the bundle, so the repository does not store the word lists. Each dictionary parses on first use and stays in memory. The editor plugin collects words on visible lines only, skipping frontmatter, code, URLs, wiki links, tags, math, acronyms, camelCase, and words with digits, and it leaves the word under the cursor alone while it is being typed. Results are cached per language set, so only new words reach the backend. Vault languages live in local storage per vault, matching decision 3's rule that Jotter never writes settings into the vault; a note's `lang` property, the Pandoc key, overrides them. A note in a language without a dictionary gets no underlines, since underlining every word helps no one. The personal word list sits in the app data `dictionaries/personal.txt` file for the same reason, so it is per computer, not per vault.
- **Bring-your-own AI (`src-tauri/src/ai/`, `src/lib/AiPanel.svelte`, `src/lib/aiText.ts`)**: Every request goes through Rust, so the webview never holds an API key and the CSP needs no AI hosts. `ai.json` in the app data folder stores the provider, endpoints, models, and writing style, never keys. Keys live in the OS credential store (`keyring`: Windows Credential Manager, macOS Keychain, Secret Service on Linux), behind a `SecretStore` trait; a platform without a store refuses to save a key rather than writing a file. Each saved key records its endpoint origin, and Jotter sends it only to that origin, so changing the base URL requires entering the key again. Cloud URLs must use HTTPS; plain HTTP is allowed for loopback hosts and for Ollama, which receives no key. The HTTP client follows no redirects, so a redirect cannot carry a key to another host, and uses the OS TLS stack (`native-tls`) because `ring` does not build on Windows ARM64 without extra C headers.
- **Markdown protection for AI**: Before rewrite and translate, `guard.rs` replaces fenced code, math, frontmatter, inline code, link destinations, wiki links, embeds, HTML tags, URLs, tags, footnote references, and block IDs with numbered placeholders (`⟦J0⟧`). The reply must contain each placeholder exactly once, or Jotter rejects it and leaves the note unchanged. A reply cut off by the output limit is also rejected, so a partial rewrite never replaces text. Whole-note commands skip YAML frontmatter on the frontend.
- **Prompts and writing style**: Jotter's fixed system prompt comes first. It treats note text inside `<note>` tags as data and forbids following instructions found there. The user's writing style follows in `<style>` tags, which the prompt ranks below those rules, so editing the style cannot turn off Markdown protection. Polish, the other rewrites, and summaries use the style; translation and grammar-only fixes skip it so they do not reword the text.
- **Applying results**: The panel captures the target range and the document object. Applying checks that the document is still the same object, so any edit, reload, or tab switch since the request started rejects the result. The change carries `isolateHistory`, so one `Ctrl+Z` undoes it. Cancelling drops the request future in Rust, which closes the connection, and the store ignores any late reply.
- **Interface Language (`src/lib/i18n.svelte.ts`, `messages/*.json`)**: Paraglide JS compiles each message to a typed function, so a missing or misspelled key fails `svelte-check`, and Vite drops unused messages. Generated code goes to `src/lib/paraglide/`, which is gitignored; `npm run check`, `npm test`, and the Vite plugin regenerate it. The compiler fetches the message-format plugin from jsDelivr at a pinned version on the first build. Paraglide's default `setLocale` reloads the page, which would drop unsaved editor state, so Jotter overrides `getLocale` with a getter backed by a `$state` value: every `m.key()` call in a template re-runs when the language changes. Label tables in stores use getters for the same reason. Messages that wrap a value in markup (`<strong>`, `<code>`, `<kbd>`) render that value as a placeholder and split the text around it (`splitSlots`), so translations keep their own word order without `{@html}`; a test requires every translation to keep the English placeholder order. The tray menu and native dialog titles come from the frontend through `set_tray_labels` and dialog label arguments, with English fallbacks in Rust. Backend error messages, the scratchpad's sample note, and status messages already on screen stay in the language they were created in. Home page section titles saved by older versions in English count as defaults, so they translate too.
